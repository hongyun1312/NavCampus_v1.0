## 一、项目现状总览

### 1.1 项目定位

NavCampus（智慧校园综合导航/管理平台）是沈阳工业大学省级大学生创新创业训练计划项目，前身为一套记账系统（包名 com.hongyun.accounting），后逐步扩展为智慧校园综合管理平台。当前项目同时包含**校园导航/管理功能**（3D校园浏览、自习室预约、课表管理、天气查询、通知系统）与**遗留记账功能**（账户管理、收支记录、预算管理、分类管理、账单导入、统计聚合）。

## 二、缺陷分析（按严重程度分级）

> 分级标准：P0=致命/安全风险必须立即修复 | P1=架构性问题影响可维护性 | P2=代码质量问题 | P3=规范性与细节问题

### 2.1 P0 级缺陷（致命/安全风险，必须立即修复）

#### P0-01：README.md 虚假技术声明--简历注水红线

**问题描述**：README.md 中大量声称了项目中**完全不存在**的技术实现，这些声明若出现在简历中，在大厂面试时将被判定为"简历造假/注水"，是面试一票否决的红线。

| README 声明 | 实际代码 | 风险 |
|------------|---------|------|
| "独立基于 Java 实现 A* 路径规划算法" | 无任何 A* 相关代码 | 面试官90%会深挖A*，无法回答直接挂 |
| "基于 DDD 领域驱动的分层六边形架构" | 标准 MVC 三层架构，无领域层/防腐层 | 架构认知错误 |
| "Caffeine+Redis 多级缓存架构" | 仅 Redis 做 JWT Token 存储，无 Caffeine | 缓存架构是高频面试题 |
| "热点数据缓存命中率达99.7%" | 无缓存命中率监控代码 | 数据造假 |
| "核心导航接口响应耗时从260ms优化至55ms" | 无导航接口，无性能测试 | 数据造假 |
| "慢查询占比从12%降至0.1%以下" | 无慢查询监控 | 数据造假 |
| "基于多线程实现高并发动态避障" | 无多线程路径规划代码 | 技术造假 |
| "服务可用性稳定达99.9%" | 项目未上线，无监控系统 | 数据造假 |
| "部署耗时从2小时缩短至10分钟" | 无 Docker/CI-CD 配置 | 数据造假 |

**修复建议**：参照本文档第五章，将所有未实现的声明移除，仅保留已实现的真实功能描述。待后续真正实现后再逐步加回。

---

#### P0-02：无全局异常处理器

**问题描述**：项目没有 @ControllerAdvice / @RestControllerAdvice 全局异常处理器。Service 层抛出 RuntimeException 时，异常直接暴露给客户端，返回 Spring Boot 默认错误页面或原始堆栈信息。

**影响**：安全风险（堆栈泄露内部信息）、用户体验差（不可预测的错误格式）、不符合规范 P1-08。

**修复建议**：创建 GlobalExceptionHandler，统一捕获 RuntimeException、MethodArgumentNotValidException、AccessDeniedException 等，返回统一的 R<T> 格式。

---

#### P0-03：CORS 配置允许所有来源

**问题描述**：SecurityConfig 中 setAllowedOrigins(Arrays.asList("*"))，且10+个Controller重复标注 @CrossOrigin(origins = "*")。生产环境允许任意来源跨域是严重安全风险。

**涉及文件**：SecurityConfig.java、AuthController.java、RecordController.java 等

**修复建议**：通过环境变量配置允许的来源列表，生产环境必须限制为前端域名。

---

#### P0-04：数据库 DDL 自动生成，无版本控制

**问题描述**：application.yml 中 ddl-auto=update，表结构由 Hibernate 自动生成。DataInitializer.java 每次启动执行裸 SQL ALTER TABLE，用 try-catch 吞掉异常。

**修复建议**：ddl-auto 改为 validate/none，创建 doc/sql/ 版本管理目录，引入 Flyway，移除 DataInitializer 裸 SQL。

---

#### P0-05：无入参校验

**问题描述**：所有 DTO 和 Controller 入参均无校验注解（@NotBlank/@NotNull/@Size/@Email），未使用 @Valid。StudyRoomController 直接用 Map<String,Object> 接收参数。违反规范 P1-04。

**修复建议**：为所有 DTO 添加 JSR-380 校验注解，Controller 参数添加 @Valid，Map 参数替换为专用 DTO。

---

#### P0-06：JWT 密钥管理风险

**问题描述**：JWT 密钥可能被硬编码或明文提交 Git。JwtUtils 中 jwtSecret.getBytes() 作为 HMAC 密钥，长度不足256位将导致签名强度不够。

**修复建议**：密钥通过环境变量注入，长度至少256位（32字节）。
---

### 2.2 P1 级缺陷（架构性问题，影响可维护性和面试可信度）

#### P1-01：包名与项目定位不符

**问题描述**：根包名 com.hongyun.accounting 是项目前身记账系统的遗留命名，与当前"智慧校园导航/管理平台"定位完全不符。Maven artifactId 为 accounting，前端 package.json 名为 accounting-frontend，启动类为 AccountingApplication。

**涉及范围**：pom.xml、AccountingApplication.java、全部63个Java源文件的package声明、frontend/package.json、application.yml

**修复建议**：全量重命名为 com.hongyun.navcampus，启动类改为 NavCampusApplication，artifactId 改为 navcampus。详见第四章4.1节。

---

#### P1-02：无统一返回格式

**问题描述**：规范P1-08要求所有接口返回统一的 R<T> 结构。当前Controller返回类型极其混乱：

| Controller | 方法 | 返回类型 | 问题 |
|-----------|------|---------|------|
| AuthController | signin | ResponseEntity<?> | 无统一结构 |
| AuthController | signup | ResponseEntity<?> 返回String | 返回裸字符串 |
| RecordController | list | List<Record> | 直接返回Entity列表 |
| AdminController | getAllUsers | List<User> | **返回User实体含密码哈希！** |
| AccountController | createAccount | Account | 直接返回Entity |
| StatsController | aggregate | Object | 无类型安全 |
| StudyRoomController | getAllSeats | List<Seat> | 直接返回Entity |
| RecordController | delete | void | 无返回体 |

**修复建议**：创建 R<T> 统一响应包装类，所有接口统一返回 R<T> 格式。

---

#### P1-03：Controller 直接返回 Entity，无 VO 层

**问题描述**：规范P1-03要求Service不直接返回前端对象。当前所有Controller直接返回JPA Entity：

- AdminController.getAllUsers() 返回 User 实体 -- **密码哈希字段会序列化到JSON响应中**
- RecordController.list() 返回 Record 实体 -- 懒加载关联对象可能触发N+1查询或LazyInitializationException
- 所有Controller均无VO转换层

**修复建议**：引入VO层，Controller只返回VO，Service返回DTO/Domain，层间做转换。

---

#### P1-04：Controller 包含业务逻辑，直接调用 Repository

**问题描述**：规范P1-03要求Controller不写业务逻辑。但多个Controller直接注入并调用Repository：

- AdminController -- 直接注入4个Repository，在Controller中直接CRUD
- RecordController.create() -- Controller中组装Record对象、查找Account/Category
- TimetableController -- 直接注入3个Repository做数据转换
- AuthController -- Controller中直接操作UserRepository创建用户

**修复建议**：所有业务逻辑下沉到Service层，Controller只负责接收请求、调用Service、返回响应。

---

#### P1-05：无 Maven 多模块结构

**问题描述**：规范第2.2节要求Maven多模块架构，模块间严格单向依赖。当前为单模块结构，记账功能与校园功能混在一起，无法独立编译、测试和部署。

**修复建议**：拆分为6个Maven子模块。详见第四章4.2节。

---

#### P1-06：JPA 使用，需迁移到 MyBatis-Plus

**问题描述**：规范明确要求使用MyBatis且禁止混用JPA。当前项目全部使用JPA/Hibernate，包括14个Entity和14个JpaRepository。用户已决定全量迁移到MyBatis-Plus。

**涉及文件**：所有14个Entity、14个Repository

**修复建议**：详见第四章4.3节迁移方案。

---

#### P1-07：权限控制不完整

**问题描述**：仅AdminController有类级@PreAuthorize注解，其余Controller均无权限注解：

- RecordController -- delete()虽有Service层校验但Controller层无注解保护
- AccountController -- 无任何权限校验
- StudyRoomController -- updateSeatStatus等管理员操作无ADMIN权限校验
- NotificationController -- 创建通知无权限校验

**修复建议**：为所有写操作添加@PreAuthorize注解，管理员操作添加hasRole('ADMIN')校验。

---

#### P1-08：实体缺少审计字段

**问题描述**：规范要求建表需有完整审计字段。当前大部分实体仅有createdAt，无updateTime/createBy/updateBy/deleted。Seat、Account、Budget、Category、Reservation、Feedback、Exam等7个实体完全无审计字段。

**修复建议**：创建BaseEntity基类，包含createTime/updateTime/createBy/updateBy/deleted字段，所有实体继承。MyBatis-Plus迁移后使用自动填充功能。

---

#### P1-09：Service 无接口/实现分离

**问题描述**：所有12个Service都是具体类直接标注@Service，无接口定义。不利于扩展、测试和AOP代理，也不符合企业级项目"面向接口编程"惯例。

**修复建议**：为每个Service提取接口，实现类命名XxxServiceImpl。

---

#### P1-10：混合业务域，职责不清

**问题描述**：记账业务与校园业务混在同一包下。前端路由也混合（如/dashboard既是记账仪表盘又在校园导航菜单下）。前端App.vue中导航菜单将"校园财务"与"探索校园"并列，定位模糊。

**修复建议**：通过多模块拆分将记账归入navcampus-finance，校园归入navcampus-campus。前端路由按业务域分组。
---

### 2.3 P2 级缺陷（代码质量问题）

#### P2-01：完全没有测试代码

**问题描述**：backend/src/test 目录下无任何测试文件。规范要求完整的测试覆盖。对于简历中声称"全链路性能调优"的项目，零测试覆盖是重大短板。

**修复建议**：建立单元测试（Service层Mockito）+ 集成测试（SpringBootTest + TestContainers）+ API测试（MockMvc）三层测试体系。优先覆盖核心业务（自习室预约、记账、认证）。

---

#### P2-02：API文档注解缺失

**问题描述**：已引入springdoc-openapi依赖但未使用任何@Tag/@Operation/@Parameter注解，Swagger UI页面无接口描述信息。

**修复建议**：为所有Controller添加OpenAPI注解，按业务域分组。

---

#### P2-03：WeatherController 每次请求创建 RestTemplate

**问题描述**：WeatherController 中 `private final RestTemplate restTemplate = new RestTemplate()` 直接实例化，未注册为Spring Bean。每次创建新实例浪费资源，且无法配置连接池、超时等。

**修复建议**：注册RestTemplate为Bean，配置连接池和超时参数，或使用WebClient（响应式）。

---

#### P2-04：StudyRoomService.getStats() 性能问题

**问题描述**：getStats() 方法使用 `seatRepository.findAll()` 和 `reservationRepository.findAll()` 全表加载后用stream过滤，数据量大时性能极差。规范的N+1查询反模式。

**修复建议**：使用自定义查询（COUNT查询）在数据库层面聚合统计。

---

#### P2-05：无分页

**问题描述**：所有列表接口（getAllUsers、getAllRecords、getAllSeats、getNotifications等）均无分页，返回全量数据。数据量增长后接口响应变慢，内存溢出风险。

**修复建议**：引入MyBatis-Plus分页插件，所有列表接口支持分页参数。

---

#### P2-06：无限流机制

**问题描述**：无接口限流配置，高并发场景下可能被刷接口。规范要求"接口限流"。

**修复建议**：引入Redis+Lua限流或Sentinel，对认证接口、预约接口实施限流。

---

#### P2-07：无Docker/部署配置

**问题描述**：无Dockerfile、无docker-compose.yml、无CI/CD配置。README声称"Docker容器化部署"但实际不存在。规范第十七章有详细的Docker规范要求。

**修复建议**：创建多阶段Dockerfile、docker-compose.yml（含MySQL/Redis/应用编排），配置Gitea Actions CI/CD。

---

#### P2-08：生产配置不当

**问题描述**：application.yml中 show-sql: true 应仅用于开发环境。logging.level 设为DEBUG也应区分环境。无多环境配置文件分离（application-dev.yml / application-prod.yml）。

**修复建议**：使用Spring Profiles，创建application-dev.yml和application-prod.yml，通过spring.profiles.active切换。

---

#### P2-09：JwtUtils 使用 System.err.println

**问题描述**：JwtUtils.java 中使用System.err.println输出错误日志，而非SLF4J Logger。规范要求"基于SLF4J+Logback实现分级日志"。

**修复建议**：替换为logger.error()，使用SLF4J。

---

#### P2-10：DataInitializer 中硬编码初始化逻辑

**问题描述**：DataInitializer 中硬编码创建20个座位（initSeats方法在StudyRoomService中），默认管理员账号密码以占位符形式存在但逻辑在启动时执行。这种初始化方式不灵活且不可追溯。

**修复建议**：使用data.sql或Flyway迁移脚本进行数据初始化，通过配置控制是否执行。

---

### 2.4 P3 级缺陷（规范性与细节问题）

#### P3-01：编码风格不一致

**问题描述**：部分Entity使用@Data注解（如User、Record、Seat、Course），部分手写getter/setter（如Notification）。混合使用两种风格。

**修复建议**：统一使用Lombok @Data注解（迁移MyBatis-Plus后实体可用@TableName等注解）。

---

#### P3-02：遗留无用文件

#### 依赖变更

**移除依赖**：

```xml
</dependency>
```

#### Entity 改造

**改造前（JPA）**：
```java
@Data
@Entity
@Table(name = "users")
public class User implements UserDetails {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    // ...
}
```

**改造后（MyBatis-Plus）**：
```java
@Data
@TableName("users")
public class User implements UserDetails {
    @TableId(type = IdType.AUTO)
    private Long id;
    // ...
}
```

**主要变更点**：
| JPA注解 | MyBatis-Plus注解 | 说明 |
|---------|-----------------|------|
| @Entity | @TableName | 类级别表名映射 |
| @Table(name="x") | @TableName("x") | 合并为一个注解 |
| @Id | @TableId | 主键标识 |
| @GeneratedValue(IDENTITY) | @TableId(type=IdType.AUTO) | 自增策略 |
| @Column(name="x") | @TableField("x") | 字段映射 |
| @Column(nullable=false) | 无直接等价 | 通过DDL约束 |
| @ManyToOne | 无（通过XML/注解查询） | 关联查询改为手动 |
| @OneToMany | 无 | 同上 |
| @PrePersist | MetaObjectHandler | 自动填充 |
| @Enumerated(EnumType.STRING) | @TableField + TypeHandler | 枚举处理 |

#### Repository 改造

**改造前（JPA Repository）**：
```java
public interface UserRepository extends JpaRepository<User, Long> {
    boolean existsByUsername(String username);
    Optional<User> findByUsername(String username);
}
```

**改造后（MyBatis-Plus Mapper）**：
```java
@Mapper
public interface UserMapper extends BaseMapper<User> {
    default boolean existsByUsername(String username) {
        return selectCount(new LambdaQueryWrapper<User>()
            .eq(User::getUsername, username)) > 0;
    }

    default Optional<User> findByUsername(String username) {
        return Optional.ofNullable(selectOne(new LambdaQueryWrapper<User>()
            .eq(User::getUsername, username)));
    }
}
```

**关联查询改造**：JPA的@ManyToOne懒加载改为MyBatis-Plus的自定义查询或XML映射：
```java
// RecordMapper.java
@Mapper
public interface RecordMapper extends BaseMapper<Record> {
    @Select("SELECT r.*, a.name as account_name, c.name as category_name " +
            "FROM records r LEFT JOIN accounts a ON r.account_id = a.id " +
            "LEFT JOIN categories c ON r.category_id = c.id " +
            "WHERE r.user_id = #{userId}")
    List<RecordVO> selectRecordsWithDetail(@Param("userId") Long userId);
}
```

#### 迁移步骤（按模块）

1. **navcampus-common模块**：创建BaseEntity（含审计字段+自动填充）
2. **navcampus-system模块**：迁移User/Notification/SystemLog/VerificationCode（4个Entity + 4个Mapper）
3. **navcampus-campus模块**：迁移Seat/Reservation/Course/Exam/Feedback/Teacher（6个Entity + 6个Mapper）
4. **navcampus-finance模块**：迁移Account/Record/Budget/Category（4个Entity + 4个Mapper）
5. **Service层改造**：将JpaRepository调用改为BaseMapper/自定义Mapper调用
6. **配置改造**：移除JPA相关配置，添加MyBatis-Plus配置
7. **数据库脚本**：根据现有Entity生成完整的DDL脚本

#### 配置变更

**application.yml 改造**：
```yaml
# 移除
spring:
  jpa:
    hibernate:
      ddl-auto: update
    show-sql: true

# 新增
mybatis-plus:
  mapper-locations: classpath*:/mapper/**/*.xml
```

#### 风险与注意事项

1. **JPA懒加载移除**：原JPA的@ManyToOne(fetch=LAZY)在序列化时可能触发N+1，迁移后改为显式JOIN查询，反而更可控
2. **@PrePersist迁移**：MyBatis-Plus使用MetaObjectHandler实现自动填充，需创建配置类
3. **ddl-auto移除**：迁移后需手动管理DDL，建议同时引入Flyway
4. **事务管理**：Spring的@Transactional在MyBatis下同样有效，无需改动
5. **分页**：MyBatis-Plus自带分页插件，替换原有无分页查询

### 4.4 统一返回格式实现方案

#### R<T> 统一响应类（放入navcampus-common模块）

```java
package com.hongyun.navcampus.common.core;

@Data
@Schema(description = "统一响应结果")
public class R<T> {
    @Schema(description = "状态码：200成功，其他失败")
    private int code;
    @Schema(description = "提示信息")
    private String msg;
    @Schema(description = "响应数据")
    private T data;

    public static <T> R<T> ok() { return ok(null); }
    public static <T> R<T> ok(T data) { return ok("操作成功", data); }
    public static <T> R<T> ok(String msg, T data) {
        R<T> r = new R<>();
        r.setCode(200); r.setMsg(msg); r.setData(data);
        return r;
    }
    public static <T> R<T> fail(String msg) { return fail(500, msg); }
    public static <T> R<T> fail(int code, String msg) {
        R<T> r = new R<>();
        r.setCode(code); r.setMsg(msg);
        return r;
    }
}
```

### 4.5 全局异常处理方案（放入navcampus-framework模块）

```java
package com.hongyun.navcampus.framework.handler;

@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public R<Void> handleBusiness(BusinessException e) {
        log.warn("业务异常: {}", e.getMessage());
        return R.fail(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public R<Void> handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
            .map(f -> f.getField() + ": " + f.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return R.fail(400, msg);
    }

    @ExceptionHandler(AccessDeniedException.class)
    public R<Void> handleAccessDenied(AccessDeniedException e) {
        return R.fail(403, "无权限访问");
    }

    @ExceptionHandler(Exception.class)
    public R<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return R.fail(500, "系统内部错误，请稍后重试");
    }
}
```

**自定义业务异常**（放入navcampus-common）：
